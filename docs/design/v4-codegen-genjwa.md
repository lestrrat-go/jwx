# Refactor genjwa (JWA Algorithm Generator)

## Motivation

`genjwa/main.go` (517 lines) generates algorithm type definitions, accessor functions, registration/lookup, marshal/unmarshal, and tests. Unlike the other generators, it does not use `codegen.Object` — it has its own `AlgYAML`, `Algorithm`, and `Element` structs and parses YAML directly via `goccy/go-yaml`.

The two main functions, `Generate` (265 lines) and `GenerateTest` (163 lines), are moderately sized but pack multiple conceptually separate concerns into each.

## Current Structure

```
Types:
  AlgYAML     -- top-level YAML container
  Algorithm   -- one algorithm type (e.g., SignatureAlgorithm)
  Element     -- one algorithm value (e.g., RS256)

_main()                   lines 48-89
  → Generate(t)           lines 91-355   (265 lines)
  → GenerateTest(t)       lines 357-517  (163 lines)
```

No helper functions are shared with other generators. genjwa does not use `yaml2json`, `IsPointer`, `fieldStorageType`, or `codegen.Object` at all.

The orchestrator:

```go
func Generate(t Algorithm) error {
    var buf bytes.Buffer
    o := codegen.NewOutput(&buf)
    o.R("// Code generated by tools/cmd/genjwa/main.go. DO NOT EDIT.")
    o.LL("package jwa")

    generateImports(o, t)
    generateGlobalState(o, t)
    generateInit(o, t)
    generateAccessors(o, t)
    generateTypeDefinition(o, t)
    generateConstructorAndEmpty(o, t)
    generateRegistration(o, t)
    generateMarshalJSON(o, t)

    return o.WriteFile(t.Filename, codegen.WithFormatCode(true))
}
```

### Keep `Algorithm`/`Element` structs local

These types are specific to algorithm generation and are not useful to other generators. They should stay in `genjwa/main.go`. Unlike the other generators that use `codegen.Object`, genjwa's simpler data model doesn't benefit from shared types.

### Conditional `symmetric` handling

The `symmetric` flag causes branching in:
- Struct definition (adds `isSymmetric` field)
- `NewXxx` function (adds `IsSymmetric` option processing)
- `IsSymmetric()` method (conditionally emitted)
- Test generation (symmetric value check test)

Currently this is handled with inline `if t.Symmetric` checks. This is fine — the branching is clear and localized. The refactoring just moves these checks into smaller functions where each deals with one concern.

### `token_reference` handling

Some elements use `token_reference` instead of a string literal `value` for their algorithm name (e.g., referencing `tokens.RS256` instead of `"RS256"`). This is already clean — the code checks `if e.TokenReference != ""` and uses the reference. No change needed.

## Migration

1. Split `Generate` into the functions listed above
2. Split `GenerateTest` similarly
3. No shared library dependencies needed (genjwa doesn't share patterns with the other generators)
4. Verify with `make generate-jwa` that output is unchanged
